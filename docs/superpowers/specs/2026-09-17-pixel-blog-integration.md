# 像素首页接入与项目整理

## 已确认目标

将已确认的蘑菇版像素预览接入正式 Hexo 博客，清理明确废弃的实现，验证后推送并确认线上更新。不引入框架，不删除文章和个人未提交文件。

## 接入方式

- 保留 `scripts/scrapbook/model.js` 的真实文章数据和现有首页布局、搜索、主题切换、音乐与目录功能。
- 在 `scripts/scrapbook/render-home.js` 的首页 Hero 中加入蘑菇、金币、星星、云和可点击问号砖块；将工具盒装饰为预览中的掌机外观，继续使用现有音乐控制协议，不建立第二套播放器。
- 新增 `source/js/pixel-world.js` 与 `source/css/pixel-world.css`，只负责像素图案与小游戏。不复制预览的假文章、假导航、Tweak 调试面板或页面外壳。
- 蘑菇图案共用一份定义：首页与文章回顶调用同一渲染函数，移除回顶代码中重复的颜色和像素矩阵。保持文章页回顶原有行为。
- 首页可见文案不再包含“手账”；保留 `scrapbook` 内部类名和文件名，避免为改名扩大改动。

## 游戏行为

沿用现有已确认蘑菇预览：开始、跳跃、计分、逐步加速、碰撞结束、重试、暂停和退出。空格/方向上键以及触屏按钮可跳跃。键盘事件限定在游戏控件内，不抢正文浏览按键。

失去焦点、切换标签页或调整窗口时暂停；退出时停止动画循环。无音效，不自动开始。系统减少动态效果时停用装饰动画，游戏仍由用户主动开始。切换页面时清理监听和动画帧，不重复挂载。

## 清理与目录边界

- `source/`：文章、页面、浏览器 CSS/JS 的唯一编辑入口。
- `scripts/scrapbook/`：Hexo 首页的数据与 HTML 生成逻辑。
- `themes/stellar`：保留原主题子模块；不删除主题内部未经确认的资源。
- `public/`：Hexo 临时构建输出，不提交。
- 仓库根目录的 HTML、`css/`、`js/` 等：保留为当前 Pages `main / root` 的发布产物，禁止手工维护；本轮不更换 Pages 设置或迁移发布分支。
- 增加一个显式静态同步命令，将 `public/` 的生成文件同步到根目录，检查路径不越界、不覆盖源码；不做全目录删除。同步后检查 Git 差异，删除本轮明确废弃的对应产物。
- 删除已不再被页面引用的 `source/css/custom.css` 和对应 `css/custom.css`。其他资源只有确认无引用、无配置依赖后才删除；历史 QA 材料、个人文件和独立预览文件保留。
- 修订 README，写清编辑入口、验证、同步、推送与线上检查。移除文档中将 `hexo deploy` 当作本仓库默认发布流程的误导；不调用可能覆盖源码分支的旧部署命令。
- 保留 `.nojekyll` 和 `.gitmodules`，避免重现已修复的部署问题。

## 验收

1. 使用现有 40 项测试及 Hexo clean/build；不新增测试文件或测试层。
2. 实际浏览器检查桌面和 390px/320px：首页像素图案、问号交互、游戏开始/跳跃/暂停/碰撞/重试/退出、无横向溢出。
3. 回归搜索、主题、工具盒，音乐缺少音源时保持禁用，不自动播放；文章目录和蘑菇回顶可用。
4. 源码与发布产物同步，提交仅包含任务文件，保留 `.workbuddy/memory/2026-07-24.md` 的用户修改。
5. 推送后检查部署与线上新资源；推送成功不等于上线成功。若失败，依据实际日志继续定位，不仅要求用户刷新。

## 风险与限制

根目录发布产物仍与源码共存，这是当前 Pages 配置要求，不应误删为冗余。此轮只规范生成和同步边界，不进行另一次部署架构迁移。游戏是轻量博客彩蛋，不新增游戏引擎或联网排行。
